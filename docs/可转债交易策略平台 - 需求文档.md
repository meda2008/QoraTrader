## 2. 策略插件化架构

### 2.1 策略接口规范

```python
# 策略基类定义
from abc import ABC, abstractmethod
from typing import Dict, List, Any, Optional
from dataclasses import dataclass
import pandas as pd

@dataclass
class StrategyConfig:
    """策略配置基类"""
    strategy_name: str
    strategy_version: str
    author: str
    description: str

@dataclass
class SignalResult:
    """信号结果"""
    action: str  # BUY/SELL/HOLD
    stock_code: str
    quantity: int
    price: Optional[float] = None
    reason: str = ""
    confidence: float = 1.0

class BaseStrategy(ABC):
    """策略基类 - 所有策略必须继承此类"""

    def __init__(self, config: StrategyConfig):
        self.config = config
        self.name = config.strategy_name
        self.positions = {}  # 持仓信息
        self.account_info = {}  # 账户信息

    @abstractmethod
    def get_optimization_space(self) -> Dict[str, List]:
        """返回策略参数优化空间"""
        pass

    @abstractmethod
    def initialize(self, params: Dict[str, Any]) -> bool:
        """策略初始化"""
        pass

    @abstractmethod
    def on_bar(self, bar_data: pd.DataFrame) -> List[SignalResult]:
        """Bar数据回调 - 主要信号生成逻辑"""
        pass

    @abstractmethod
    def on_tick(self, tick_data: Dict) -> List[SignalResult]:
        """Tick数据回调 - 可选实现"""
        pass

    @abstractmethod
    def on_order_filled(self, order_info: Dict) -> None:
        """订单成交回调"""
        pass

    @abstractmethod
    def on_position_update(self, position_info: Dict) -> None:
        """持仓更新回调"""
        pass
        
    @abstractmethod
    def on_error(self, error_code: int, error_msg: str) -> None:
        """错误回调 - 处理系统或交易接口的错误"""
        pass

    @abstractmethod
    def get_risk_params(self) -> Dict[str, Any]:
        """获取风控参数"""
        pass

    def on_market_open(self) -> None:
        """开盘回调 - 可选实现"""
        pass

    def on_market_close(self) -> None:
        """收盘回调 - 可选实现"""
        pass
        
    def on_shutdown(self) -> None:
        """系统关闭回调 - 用于策略状态持久化等清理工作"""
        pass

    def get_strategy_status(self) -> Dict[str, Any]:
        """获取策略状态"""
        return {
            "name": self.name,
            "positions": self.positions,
            "account_info": self.account_info
        }
```

## 4. 可转债量价突破策略实现示例

### 4.1 策略核心逻辑 (伪代码)

```python
# strategies/convertible_bond_volume_breakout/strategy.py
from strategies.base_strategy import BaseStrategy, StrategyConfig, SignalResult
import pandas as pd
from typing import Dict, List, Any, Optional

class ConvertibleBondVolumeBreakoutStrategy(BaseStrategy):
    """可转债量价突破策略"""

    def initialize(self, params: Dict[str, Any]) -> bool:
        # ... 初始化参数 ...
        self.signal_count = params.get('signal_count', 3)
        self.volume_ratio = params.get('volume_ratio', 2.0)
        self.stop_loss_pct = params.get('stop_loss_pct', 0.01)
        self.profit_drawdown_pct = params.get('profit_drawdown_pct', 0.20)
        self.negative_bars = params.get('negative_bars', 2)
        self.max_positions = params.get('max_positions', 5)
        # ... 策略状态初始化 ...
        self.bar_data_cache = {}
        self.position_cost = {}
        self.position_high = {}
        return True

    def on_bar(self, bar_data: pd.DataFrame) -> List[SignalResult]:
        # ... Bar数据缓存逻辑 ...
        signals = []
        for stock_code in bar_data['stock_code'].unique():
            # ... 更新缓存 ...
            buy_signal = self._check_buy_signal(stock_code)
            sell_signal = self._check_sell_signal(stock_code)
            if buy_signal: signals.append(buy_signal)
            if sell_signal: signals.append(sell_signal)
        return signals

    def _check_buy_signal(self, stock_code: str) -> Optional[SignalResult]:
        """检查买入信号 - 基于第5.1节逻辑"""
        bars = self.bar_data_cache.get(stock_code, [])
        if len(bars) < self.signal_count + 1: return None
        if stock_code in self.positions or len(self.positions) >= self.max_positions: return None
        
        current_time = pd.to_datetime(bars[-1]['time'])
        if current_time.hour == 14 and current_time.minute >= 50: return None

        is_signal_triggered = all(
            bars[-(i+1)]['volume'] >= bars[-(i+2)]['volume'] * self.volume_ratio and
            bars[-(i+1)]['close'] > bars[-(i+2)]['close']
            for i in range(self.signal_count)
        )
        
        if is_signal_triggered:
            quantity_to_buy = self._calculate_position_size(stock_code)
            if quantity_to_buy > 0:
                return SignalResult(action='BUY', stock_code=stock_code, quantity=quantity_to_buy, reason="量价突破信号")
        return None

    def _check_sell_signal(self, stock_code: str) -> Optional[SignalResult]:
        """检查卖出信号 - 基于第5.2节逻辑"""
        if stock_code not in self.positions: return None

        bars = self.bar_data_cache.get(stock_code, [])
        current_price = bars[-1]['close']
        cost_price = self.position_cost.get(stock_code)
        high_price = self.position_high.get(stock_code, cost_price)
        self.position_high[stock_code] = max(high_price, current_price)

        if current_price <= cost_price * (1 - self.stop_loss_pct):
            return SignalResult(action='SELL', stock_code=stock_code, quantity=self.positions[stock_code]['quantity'], reason="止损")

        drawdown = (self.position_high[stock_code] - current_price) / self.position_high[stock_code]
        if drawdown >= self.profit_drawdown_pct:
            return SignalResult(action='SELL', stock_code=stock_code, quantity=self.positions[stock_code]['quantity'], reason="浮盈回撤止盈")

        if len(bars) >= self.negative_bars and all(b['close'] < b['open'] for b in bars[-self.negative_bars:]):
            return SignalResult(action='SELL', stock_code=stock_code, quantity=self.positions[stock_code]['quantity'], reason=f"连续{self.negative_bars}根阴线")

        current_time = pd.to_datetime(bars[-1]['time'])
        if current_time.hour >= 14 and current_time.minute >= 56 and current_time.second >= 50:
            return SignalResult(action='SELL', stock_code=stock_code, quantity=self.positions[stock_code]['quantity'], reason="收盘前强制平仓")
        
        return None
    
    # ... 其他回调方法实现 ...
```

## 5. 策略逻辑设计

### 5.1 开仓逻辑

* **触发条件**：连续`N`次(可配置, `signal_count`)出现以下信号：
    * 当前bar成交量 ≥ 上一根bar成交量 × `M`倍(可配置, `volume_ratio`)
    * 当前bar收盘价 > 上一根bar收盘价
* **执行动作**：满足条件后立即买入。

### 5.2 平仓逻辑

* **止损条件**：开仓后亏损达到`X%`(可配置, `stop_loss_pct`)。
* **止盈条件**：浮盈回撤达到`Y%`(可配置, `profit_drawdown_pct`)。
* **技术止损**：连续出现`Z`个(可配置, `negative_bars`)阴线bar。
* **强制平仓**：`14:56:50`(可配置)强制平仓所有未平仓标的。

### 5.3 时间控制

* **开仓限制**：`14:50:00`(可配置)后禁止开新仓。
* **收盘平仓时间**：`14:56:50`(可配置)。

## 6. 交易执行细节

### 6.1 买入执行逻辑
* **盘口检查流程**：
    a.  检查卖一档位：若卖一挂单量 ≥ 目标手数，使用卖一价格下单。
    b.  检查卖二档位：若卖一不足且卖二价格 ≤ 卖一价格 × (1 + 0.01)（价差阈值可配），则使用卖二价格下单剩余手数。
    c.  滑点控制：总体买入滑点不超过`0.02`（可配）。
* **订单策略**：优先使用限价单。

### 6.2 卖出执行逻辑
* **滑点容忍度**：卖出滑点可达`0.03`（可配），优先保证成交。
* **订单类型**：支持限价单/市价单可配置选择。
* **紧急卖出**：风控触发时优先使用市价单。

### 6.3 订单重试机制
* **重试策略**：
    * 买入重试：最多`3`次，间隔`500ms`。
    * 卖出重试：最多`5`次，间隔`300ms`。
    * 风控卖出重试：最多`10`次，间隔`100ms`。
* **价格调整策略**：
    * 买入重试时可适当提价（最大`0.5%`）。
    * 卖出重试时可适当降价（最大`1%`）。
* **失败处理**：记录日志、发送告警、跳过或继续重试。

### 6.4 盘口数据需求
* 实时五档行情（买一到买五、卖一到卖五的价格和挂单量）。
* 数据更新频率：tick级别。

## 7. 风险控制机制

### 7.1 实时账户监控
* **数据获取**：实时账户资产、盈亏、持仓明细。
* **更新频率**：每`30`秒（可配）更新一次。
* **计算逻辑**：实时计算账户回撤、当日回撤和实时净值。

### 7.2 账户级风控
* **回撤监控**：账户总回撤超过`1%`（可配）时触发风控。
* **风控动作**：立即停止开仓、清仓所有持仓、当日禁止交易。
* **风控重置**：次日开盘前重置。

### 7.3 个股级风控
* **实时监控**：每只股票的实时盈亏和浮盈最高点。
* **止损触发**：亏损达到`1%`（`stop_loss_pct`）立即卖出。
* **止盈触发**：浮盈回撤达到`20%`（`profit_drawdown_pct`）立即卖出。

### 7.4 仓位管理
* **分仓数量**：`5`只（可配, `max_positions`）。
* **仓位分配**：平均分配，单只仓位为总资金的 `1 / max_positions`。
* **动态调整**：根据实时账户资金动态计算可开仓金额。

### 7.5 系统级风控 (新增)
* **最大订单速率限制**：防止程序BUG导致向交易所发送大量废单（例如，每秒不超过10笔）。
* **最大持仓集中度限制**：单一标的持仓市值不能超过账户总资产的指定比例（例如，30%）。
* **手动“冻结”开关**：系统应提供一个紧急“拍平”按钮，可以一键撤销所有挂单并清仓所有头寸。
* **交易接口连接状态监控**：实时监控与券商API的连接状态，断开时立即告警并暂停决策。

### 9.3 回测评价指标

* **风险指标**: 最大回撤、平均回撤、胜率、盈亏比、波动率。
* **交易指标**: 交易次数、换手率、平均持仓时间、滑点成本估算。

## 10. 标的筛选逻辑

### 10.1 基础筛选
* **成交活跃度**: 当日成交量前`5`名(可配)。
* **流动性要求**: 最小成交额阈值。

### 10.2 风险过滤
* **强赎风险**: 排除已公告强赎、转股价值超阈值、临近触发条件的标的。
* **退市风险**: 排除`ST`、`*ST`、暂停上市、即将到期（<30天）的标的。
* **其他风险**: 排除停牌。

## 12. 非功能性需求 (新增)

### 12.1 性能要求
* **延迟**: 行情接收到策略处理完成的平均延迟 < 10ms。
* **吞吐量**: 系统支持至少20个不同策略并发运行。
* **资源占用**: 监控并控制CPU和内存的合理占用。

### 12.2 可靠性与可用性
* **服务高可用**: 核心交易引擎在交易时段 `99.9%` 可用。
* **断线重连**: 行情和交易API具备自动断线重连和状态恢复机制。
* **数据持久化**: 策略状态、持仓、订单等关键信息需可靠地持久化到数据库。

### 12.3 安全性
* **配置加密**: 账户密码、API Key等敏感信息必须加密存储。
* **访问控制**: UI界面需有登录认证和权限控制。

### 12.4 可维护性
* **结构化日志**: 所有模块输出结构化日志（如JSON），便于查询分析。
* **配置中心化**: 所有配置项统一管理，避免硬编码。

## 13. 部署与运维 (新增)

### 13.1 部署方案
* **容器化**: 推荐使用 Docker 进行容器化部署，提供 `docker-compose.yml` 实现一键部署。
* **环境分离**: 区分开发、测试、生产环境。

### 13.2 监控与告警
* **系统监控**: 监控服务器的CPU、内存、磁盘、网络等基础指标。
* **应用监控**: 监控交易引擎健康状态、策略PNL、订单成交率、API延迟等。
* **告警机制**: 在触发关键事件（如风控触发、API断连、程序异常）时，通过邮件、钉钉、微信等方式发送实时告警。
